This is a bounded ordinary Markdown authoring profile, not a new portable schema version. Shared plan `AUTHORING-METADATA.md` informs diagnostics; parser success alone does not prove complete conformance.

Allowed transformations are recognizable checkbox task syntax only: uppercase X becomes x; redundant whitespace inside the checkbox becomes canonical space/x; `*` or `+` task markers become `-`. Text after the checkbox, IDs, status, metadata, unsupported stages, unknown text, comments/fences and newline style remain unchanged. Ambiguous/missing identity, owner, stage or acceptance are diagnosed with line/field/action rather than invented. No interactive semantic editing is included in this first deterministic delivery: owners edit the reported source fields themselves, then preview again. The optional interactive proposal mode remains a follow-up, explicitly disabled rather than fabricated.

CLI: `wazi repair [--save-candidate] [--data DIR] FILE`; `wazi repair --apply-candidate ID [--data DIR]`. Preview performs no writes. Explicit save creates a private immutable candidate outside the source repository. Apply requires the exact candidate identity, source digest and durable original backup. Source mode is preserved; special permission bits and symlink components are refused. Candidate/private directories are owner-only. Cooperating repair processes serialize; external editors do not share that lock, so identity/digest are rechecked immediately before replacement and residual external-editor race limits are disclosed.

AI is a separately qualified extension. `--ai` fails visibly disabled without loading dotenv or making a request. Only a future qualified explicit AI invocation may load the primary working directory's `.env` or explicit `--env-file`, with process environment precedence; never load the selected plan's environment. The host/Mac startup path stays read-only and never loads dotenv. Frozen portable contract bytes and configured Three.js checkout remain unchanged.
