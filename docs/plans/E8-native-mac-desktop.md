Acceptance: A locally built Wazi.app opens the existing observatory without browser/native title-bar chrome or developer-tool prerequisites; source plans/code remain read-only, private state remains Go-owned, and changed behavior is verified in actual WKWebView before independent review, rebase merge and landed verification.

## Context, scope and discovery

[ADR 0003](../adr/0003-platform-desktop-shells.md) records the accepted platform choice. Current baseline is landed E3 candidate `e667bfc7`: Go loopback host, relative frontend HTTP requests with session capability, Node subprocess parser located relative to repository working directory, filesystem sidecars and private AI receipts. No Swift application, bundle launcher or native window bridge exists. The preserved local Three.js checkout is build-time input only; do not edit or require it at runtime. There is no fresh code graph; discovery used `cmd/wazi/main.go`, `internal/observatory/http.go`, `src/observatory-api.mjs`, `package.json`, architecture/data-flow and the actual landed receipts.

Six planned use cases are recorded in [usecases.json](../desktop/usecases.json): launch, frameless navigation, selected-project observatory, confinement, recovery and self-contained local packaging. Existing E3 flows remain shared; this phase neither implements missing Serenity integration nor changes portable contract0.0.1. The inspector must still show unavailable context honestly.

In scope: native AppKit/WKWebView shell, bundled host/parser/assets, explicit owned-process lifecycle, minimal window-action bridge, packaged discovery/import paths and local acceptance. Out of scope: Windows/Linux implementation, renderer redesign, autonomous tasks, source writes, Go parser rewrite, paid/live AI verification, signing-account setup, public release, updater and production deployment.

A delivered app needs no developer tools or repository cwd. Freeze deployment target, arm64/x86_64 support and actual test machines before implementation; do not infer Intel runtime acceptance from cross-compilation. Minimum app width and drag/control geometry are measured during the native proof, with keyboard/VoiceOver and the existing responsive layouts retained.
